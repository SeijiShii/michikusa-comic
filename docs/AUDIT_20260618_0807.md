### 3.2 High

#### [AUDIT-perspective-001] O22 (B) 段階認証 (linkAccount/Google連携) の動線が未実装
- **カテゴリ**: #4 観点反映 (step 3.6 多部構成 broad-match マスク)
- **検出根拠**: `docs/_shared/auth/001__shared_auth_SPEC.md` §1 が `linkAccount({provider})`（ゲスト→Google OAuth 連携、課金/同期時）を契約、concept §1.2 も「ゲスト開始 → 課金/他端末同期時に段階認証（Clerk）」を MVP スコープに明記。しかし src 全体で `linkWith`/`authenticateWithRedirect`/`createExternalAccount`/`<SignIn`/`<UserButton`/`connectGoogle` が **0 ヒット**。`establishGuestSession` (匿名ゲスト=A) のみ実装され broad code_signals が (A) で pass、(B) 連携/アップグレード動線が丸ごと欠落。
- **影響**: ゲストが課金・他端末同期に進めない（契約違反）。release wiring に先送りすると初回公開で連携不能。
- **推奨修正アクション**: `/flow:revise _shared/auth` で `linkAccount` 実装（Clerk `createExternalAccount`/OAuth 連携 + 匿名 owner_id 引き継ぎ）+ サインイン/連携 UI 動線 + 対の `signOut` 動線（step 3.10 両輪）。
- **§8 登録**: 登録推奨 (auto §3.0c シューティングで /flow:revise dispatch 予定)

#### [AUDIT-perspective-002] O22 (D) ゲスト identity 非永続 → owner churn でデータ消失リスク
- **カテゴリ**: #4 観点反映 (step 3.9 owner churn / データ保存不変条件)
- **検出根拠**: `src/services/auth/guestSession.ts` の `establishGuestSession` が **per-call `createAnonymousUser()` + Clerk `createSignInToken`(ticket)** を発行。owner-scoped データ (`comics`/`photos`/`payments` の `owner_id`、`accountRepo.deleteOwnerRows(ownerId)`) を持つが、guest identity をクライアント永続する実装 (`getStoredGuestToken`/`storeGuestToken`/`GUEST_TOKEN_KEY`/自前署名 `signGuestToken`) が **0 ヒット**。= セッション/トークン失効・リロードで新しい匿名 userId が発行され owner が churn → local-first データが orphan 化（不可逆消失）。
- **影響**: Clerk セッション失効後の再訪でゲストの全作品が見えなくなる（hana-memo/prayer-list と同型の致命バグ）。
- **推奨修正アクション**: `/flow:revise _shared/auth` で `flow-data/guest-auth-clerk-scaffold.md §1.7` の **自前署名 guest JWT 永続**（Clerk 非セッション化、sticky guest identity）を実装。正解パターン = hana-memo/bousai-bag-checker/naze-bako revise_003。
- **§8 登録**: 登録推奨

#### [AUDIT-perspective-003] O56 wired-but-missing — apple-touch-icon.png が 404
- **カテゴリ**: #4 観点反映 (step 3.5 実在チェック path-resolution)
- **検出根拠**: `index.html` が `<link rel="apple-touch-icon" href="/apple-touch-icon.png">` を wiring 済だが `public/apple-touch-icon.png` が **不在**（public/ は favicon.svg + manifest.webmanifest のみ）。grep substring は href 参照で通るが実ファイル解決で 404 確定。
- **影響**: iOS ホーム追加時にアイコン 404（リンク切れアセット公開）。
- **推奨修正アクション**: `public/apple-touch-icon.png`（180×180 PNG）を生成・配置、または index.html の参照行を削除。`/flow:revise _shared/app-shell`。
- **§8 登録**: 登録推奨

### 3.3 Medium

#### [AUDIT-dependency-001] APP_BASE_URL の localhost プレースホルダ fallback
- **カテゴリ**: #2 依存整合性 (プレースホルダ fallback)
- **検出根拠**: `src/services/payments/stripe.ts:12` `const BASE = () => process.env.APP_BASE_URL || "http://localhost:5173";`。Stripe success/cancel URL の基底。`.env.example` に記載済だが、**prod で APP_BASE_URL 未設定でもハードエラーにならず黙って localhost に飛ぶ** → 本番決済リダイレクトが壊れる（build/test/local 全 green のまま prod のみ破綻）。

- **§8 登録**: 登録推奨
